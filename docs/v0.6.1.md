# v0.6.1 - App 内检查更新功能

## 日期
2026-07-07

## 变更内容

本版本补齐了此前仅停留在配置层面的应用自动更新能力：基于已有的 Tauri Updater 插件与签名发布管线，新增前端「检查更新」完整交互 —— 启动时自动静默检查、设置页手动检查按钮、发现新版本后的确认弹窗、下载进度展示，以及下载完成后的重启确认。

---

### 1. 更新检查与安装状态机
- 新增 `useAppUpdater` hook，封装 `idle / checking / up-to-date / available / downloading / ready / error` 状态机。
- `checkForUpdate(silent)`：静默模式下无更新或出错时不打扰用户；手动模式下会明确提示"已是最新版本"或错误信息。
- `downloadAndInstall`：监听 `Started / Progress / Finished` 下载事件，实时计算并展示下载百分比。
- 下载完成后不自动重启，需用户在弹窗中主动点击"立即重启"，通过 `@tauri-apps/plugin-process` 的 `relaunch()` 生效。
- 相关实现位于 `app/src/hooks/useAppUpdater.ts`。

### 2. 更新弹窗 UI
- 新增 `UpdateModal` 组件，覆盖"发现新版本确认"、"下载进度"、"下载完成提示重启"、"更新失败"四种状态展示。
- 视觉风格与现有 `AiConfigModal` 保持一致。
- 相关实现位于 `app/src/windows/UpdateModal.tsx`。

### 3. 启动时静默检查 + 设置页手动检查入口
- `Settings.tsx` 在设置窗口挂载时自动触发一次静默检查（`checkForUpdate(true)`），发现新版本时弹出确认弹窗；无更新则无感知。
- `AppSettingsSection.tsx` 版本号旁新增"检查更新"按钮，供用户随时手动触发检查，并展示"检查中…"/"已是最新版本"等状态反馈。
- 相关实现位于 `app/src/windows/Settings.tsx`、`app/src/windows/AppSettingsSection.tsx`。

### 4. Rust 与权限配置补齐
- 新增注册 `tauri_plugin_process::init()`，为前端 `relaunch()` 提供支持（`tauri_plugin_updater` 此前已注册）。
- `capabilities/default.json` 新增 `process:allow-restart` 权限。
- 相关实现位于 `app/src-tauri/src/lib.rs`、`app/src-tauri/capabilities/default.json`。

### 5. 修复发布流水线未生成 `latest.json` 的问题（关键修复）
- 排查发现：`pnpm tauri build` 只会产出安装包与 `.sig` 签名文件，**并不会自动生成** updater 所需的 `latest.json` 清单；此前 `release.yml` 假设该文件会自动出现在 `bundle/**` 下，导致 v0.6.0 发布的 GitHub Release 里从未包含 `latest.json`，客户端检查更新时会报 `Could not fetch a valid release JSON from the remote`。
- Windows / macOS 各自的构建 job 新增手动拼装当前平台 updater 清单片段的步骤（`latest-windows.json` / `latest-macos.json`），并上传为 Release 附件。
- macOS 构建命令由仅 `--bundles dmg` 调整为 `--bundles app,dmg`：updater 所需的 `.app.tar.gz` / `.app.tar.gz.sig` 只有在包含 `app` bundle target 时才会生成。
- 新增 `publish-manifest` job（`needs: [build-windows, build-macos]`），下载两个平台的清单片段并用 `jq` 合并成最终 `latest.json`，再上传覆盖到 Release，供 `releases/latest/download/latest.json` 端点读取。
- 相关实现位于 `.github/workflows/release.yml`。
