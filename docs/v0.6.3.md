# v0.6.3 - 修复更新确认弹窗被跳过的问题

## 日期
2026-07-07

## 变更内容

修复 v0.6.1 引入的更新功能中一个关键 bug：点击"下载更新"后，"下载完成，是否立即重启"确认弹窗会一闪而过，用户来不及点击就直接被重启安装了。

### 根因

Tauri Windows 平台的 NSIS Updater 中，`update.downloadAndInstall()` 会把"下载"和"安装"两个阶段捆绑执行；而"安装"阶段由于 Windows 不允许覆盖正在运行的可执行文件，Tauri 会在内部直接调用 `std::process::exit(0)` 杀掉当前进程，交由 NSIS 完成文件替换和自动重启。这个退出动作发生在 `downloadAndInstall()` 这一次调用内部，而不是等到我们自己代码里调用 `relaunch()` 的时候，导致下载完成后我们展示的"是否立即重启"确认弹窗根本没有时间等待用户交互，进程就已经被杀掉重启了。

### 修复方式
- 将原来一次性调用的 `update.downloadAndInstall()` 拆分为两步：
  - 点击"下载更新"时只调用 `update.download(onEvent)`，此时只下载更新包到本地临时位置，不会触发进程退出。
  - 用户在"下载完成"弹窗里点击"立即重启"后，才调用 `update.install()`（此时才会真正触发 Windows 上的进程退出 + NSIS 安装 + 自动重启），随后再调用 `relaunch()` 作为非 Windows 平台的兜底。
- 点击"稍后重启"时更新包不会被安装，用户可继续使用当前版本，之后随时可以重新触发安装。
- 相关实现位于 `app/src/hooks/useAppUpdater.ts`（`downloadUpdate` / `installAndRestart` 替代原先的 `downloadAndInstall` / `restartNow`），以及 `app/src/windows/Settings.tsx` 的调用方更新。
